**Корневая причина серии:** локальные правила (клетка/колонна смотрит на соседей) не могут
гарантировать глобальный инвариант «источник — только верхний слой тела». Каждый патч
чинил один симптом и ломал другой (whack-a-mole).

## 2. Контракт оператора (2026-07-20)

1. Вода течёт вниз.
2. Сверху вода убывает равномерно по всей площади, становится ниже.
3. Равномерно по слоям: есть слой y — вода берётся только с этого слоя; запрещено
   браться со слоя y−1, пока на слое y вода ещё есть.
4. Без телепортации: движение читается как непрерывное перетекание.
5. Без воздушной пропасти между струёй и лужей; без блуждающих/дёргающихся вокселей.
6. Лужа — гидростатика по бассейну: глубина = объём / площадь дна; на бескрайнем
   полу → 1 слой; у стен/в кратере — ровная поверхность на нужной глубине.

## 3. Модель и инварианты

- Клетка: `Air` / `Fluid` / `Solid` (Glass, FloorWhite, FloorGray). Бинарная вода.
- `fluidFill` — storage 0/255, в логике CA не участвует.
- Тело воды = связная компонента Fluid (6-связность: ±x, ±y, ±z).
- Grounded-клетка тела: под ней Solid / дно мира (y=0) / Fluid тела, grounded рекурсивно.
- Scan order везде: y asc, затем z asc, затем x asc. Tie-break — тот же порядок.

| ID | Правило                                                                                                                                                                                            |
|:---|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| I1 | Масса: за тик только обмен Air↔Fluid; `count(Fluid)` неизменен                                                                                                                                     |
| I2 | Solid непроницаем; ходы только cardinal (никаких срезов углов)                                                                                                                                     |
| I3 | Гравитация первая: FALL до любых перетоков; FALL сдвигает **весь непрерывный ран** вниз на 1 (струя не рвётся на капли)                                                                            |
| I4 | Для каждого тела вычисляется цель T: достижимое пространство, заполненное снизу вверх на объём V тела                                                                                              |
| I5 | Источник цепочки — только grounded-клетка **текущего верхнего слоя** тела                                                                                                                          |
| I6 | Назначение цепочки — только Air с конечным D (см. §5), не выше frontier-клетки                                                                                                                     |
| I7 | Визуальная непрерывность: любой ход сдвигает воксель ровно на 1 клетку; цепочки не проходят через не-grounded клетки (свободное падение — только FALL, 1 клетка/тик, никаких ускорений-телепортов) |
| I8 | Детерминизм: фиксированные scan/tie-break порядки; никаких hash от позиции или номера тика                                                                                                         |
| I9 | Settle: нет падений и нет цепочек → `moved==0`; одинокая клетка: T = она сама, D=0 → не двигается                                                                                                  |

## 4. Порядок тика

```
1. READ   : full-world материалы → next[]
2. FALL   : по колоннам (x,z): ран Fluid над Air сдвигается вниз на 1 целиком
3. ENGINE : per body (6-связные компоненты, scan order):
   a. GROUNDED : пометка опорных клеток (y asc)
   b. TARGET T : §5 (reachability + bottom-up fill)
   c. FIELD D  : §5 (multi-source BFS от T по legal reverse moves)
   d. CHAINS   : до K=8 раз: §6
4. COMMIT : diff next[] → мир через SetVoxelMaterial; обновить fluidCAAabb/stats
```

## 5. Бассейн, цель T и поле D

**Бассейн:** тела, чьи flood-области касаются друг друга (по Air или через
пробоину), объединяются в один бассейн (union-find). Гидростатика считается
**одна на бассейн**: объём V = сумма тел, якорь = крупнейшее тело.

**Достижимость (flood из тела по Air):** полный BFS-flood, шаги **вниз и вбок**
(вбок — независимо от опоры; неподдерживаемая клетка — fall-entry), вверх —
никогда. Flood покрывает весь достижимый бассейн.

**Fillable:** Air-клетка с опорой снизу (Solid / Fluid / уже в T / дно мира).

**Цель T — равномерный диск по построению (контракт оператора):** ровно V
позиций из fillable flooded-кандидатов. Порядок: **(y asc, stickiness asc) →
октантный round-robin**: внутри слоя кандидаты раскладываются по 8 компасным
октантам вокруг центроида якоря, каждый октант заполняется по **радиусу** от
центроида, бюджет делится между октантами поровну (стартовый сектор ротируется
по тикам). Stickiness 0 — только клетки якорного тела (осевшая лужа не
шевелится); одиночные фрагменты (страглеры) вне диска ∉ T → ползут к нему по
градиенту D и вливаются обратно. Взятие клетки в T открывает T-support соседям
(стэкинг слоёв). Клетки падения без опоры в T не входят → висячая вода никогда
не цель (только FALL).

**Поле D:** multi-source BFS от клеток T (D=0) по телу и flooded Air, рёбра =
legal reverse moves: из c в соседа n — если n выше на 1 (падение в c) или n на том
же уровне и c поддерживаемая **или** c — живой fall-узел (под ней Air с конечным D).
D = расстояние до ближайшей клетки T; ∞ для недостижимого.

**Сцены:** сфера с пробоиной → T = лужа в бассейне (+ вода ниже обода, если
бюджет V покрывает); D протекает через пробоину наружу → слив идёт, пока уровень
выше низа пробоины. Лужа на открытом полу → T = один слой на V клеток. Столбик
1×1×N → верхние клетки ∉ T, D ведёт на пол → стекает, maxH→1. Одинокая клетка →
T = она сама. Швейцарский сыр → дыры — bay-назначения (§6).

## 6. Цепочки (исполнение)

- **K** = 8 цепочек на тело/тик (`kFluidChainBudgetPerBody`); путь ≤ L = 64
  (`kFluidChainMaxPath`) — дальние перетоки занимают несколько тиков.
- **Стоимость тика:** dests собираются один раз на тело (consumed-фильтр на
  итерациях); гард — O(1) через сводку слоя (все источники на topY:
  `dest.y < topY` → любой источник; `dest.y == topY` → нужен источник с
  `D > D_dest`, сверяем с `maxSourceD`). Debug-замер на мире 42×15×42:
  engine ≈ 7 мс/тик при активном сливе (chains ≈ 1.8 мс).
- **Источники:** grounded-клетки текущего верхнего слоя тела; пересчёт после
  каждой цепочки; обход со stride/ротацией (`chainOrdinal`) → уровень опускается
  по всей площади, а не с одного угла.
- **Назначения (gradient):** Air-соседи (вбок или вниз — никогда вверх) клеток
  тела с конечным D, отсортированные по (D, y, z, x). Внутри группы равного D —
  **ротация по `chainOrdinal`** (перелив распределяется по краям, а не lex-first
  в один угол). Цепочка разрешена, только если найдётся источник с
  `y_source > y_dest` **или** `y_source == y_dest && D_source > D_dest` →
  потенциал (Σy, ΣD) строго убывает на каждой цепочке → осцилляция/джиттер
  невозможны конструктивно.
- **Bay fallback** (если gradient-цепочек нет): bay = fillable Air ∉ T с ≥3
  боковыми соседями тела; источник — клетка верхнего слоя с ≤1 боковым соседом
  (наименее связанная). Строгий рост связности (+≥2), освобождённая клетка беем
  не становится → без циклов. Лечит статический swiss-cheese.
- **Сдвиг:** p0=источник → Air; каждая клетка пути получает Fluid следующей;
  frontier-клетка → dest. Материально меняются только p0 (→Air) и dest (→Fluid);
  путь — BFS через **grounded** клетки тела, порядок соседей: down, +x, −x, +z, −z, up.
- `moved += 1` за цепочку; FALL += длина рана.

**Сходимость:** (Σy, ΣD) строго ↓ на gradient-цепочках; FALL ↓ Σy; bay ↑ связность
монотонно. Settle достижим и финален: тело == T, D=0 на поверхности, падений нет.

**Струя без пропасти:** цепочки испускают клетку из устья каждый тик, FALL несёт
ран целиком вниз 1 клетка/тик → колонна струи непрерывна от устья до головы.

## 7. Idle fast-path + ECS frame cap

`VoxelWorld` хранит `fluidEditSerial` (uint64, bump в `SetVoxelMaterial` при
**любом** изменении материала — разбитие стекла тоже будит CA — и в
`RebuildVoxelWorldDerivedState`) и `lastFluidCaSerial`. `UpdateFluidCA`: serial
равны → return 0 без сканов. Тик с moved>0 пишет `lastFluidCaSerial =
serialAtEntry` (собственные коммиты бампают serial → следующий тик сканирует);
тик с moved==0 пишет текущий serial → сканирование прекращается.

**ECS frame cap** (`EcsWorld.cpp`): не более **2** вызовов `UpdateFluidCA` на
кадр, избыточный accumulator сбрасывается (`min(acc, interval)`) — catch-up
спираль (хич → серия тиков → буря правок → ещё хич) исключена.
