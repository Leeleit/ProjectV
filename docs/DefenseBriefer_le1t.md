## 3. Q&A-карта (30 вероятных вопросов)

**Где подробно:** `docs/DefenseAlgorithms.md` (полный reference всех 23 алгоритмов) + `docs/DefenseFAQ.md` (готовые ответы на 15+ вопросов).

### 3.1. Архитектура (8 вопросов)

**Q1. Почему C++26, а не Rust/Zig/Go?**
- Все наши зависимости (Jolt, fastgltf, VMA, Draco, Flecs) — C/C++ с нативным API.
- C++26 даёт: `std::expected` для холодных путей, `std::simd` для горячих, модули для ускорения инкрементальной сборки.

**Q2. Почему Vulkan 1.4, а не OpenGL/DX12/Metal?**
- Vulkan — явный контроль GPU (пайплайны, память, синхронизация). OpenGL — driver управляет, дорого для миллионов draw items.
- Вычислительные шейдеры нужны для мешинга и трассировки.
- Кросс-платформенный (Windows + Linux + будущий macOS через MoltenVK).

**Q3. Почему Jolt, а не PhysX/Bullet?**
- Jolt — MIT, современный, детерминированный, SIMD-оптимизирован.
- Bullet устарел, PhysX избыточен.

**Q4. Почему Flecs, а не EnTT/Bevy ECS/DOTS?**
- Flecs — header-only C++ ECS, MIT, отличная эргономика для встроенного использования в Vulkan-приложении.

**Q5. Что такое DOD и зачем?**
- Дизайн, ориентированный на данные (Data-Oriented Design): данные организованы для эффективной обработки CPU, а не для удобства иерархии классов.
- Чанк 8×8×8 = 512 вокселей, 512 байт, влезает в L1.
- `alignas(16)` → авто-векторизация в `movaps`/`vmovaps`.

**Q6. Как связаны ECS и VoxelWorld?**
- Single Source of Truth: `VoxelWorld` — единственный владелец, все мутации только через него.
- ECS (Flecs) — пассивное зеркало, обновляется 1 раз за кадр через `SyncEcsWorldState`.
- HUD читает из ECS (только чтение), не из VoxelWorld (изменяемый).

**Q7. Как боретесь с накладными расходами на обработку ошибок?**
- Гибридный подход: на холодных путях — `std::expected<T, E>`, на горячих — `bool` + `CORE_ASSERT` (вырезаются в release).

**Q8. Зачем нужен ECS-bridge, если есть VoxelWorld?**
- Flecs даёт типизированные компоненты, lock-free чтение через зеркало, разделение gameplay и render.

### 3.2. Алгоритмы (10 вопросов)

**Q9. Что такое жадный мешинг и зачем?**
- Объединяет соседние грани вокселей одного материала в один четырёхугольник (quad).
- 6 проходов на чанк: ±X, ±Y, ±Z. Сокращение граней 30–50%.

**Q10. Как работают каскадные тени (CSM)?**
- 4 каскада карты глубины 2048×2048, лямбда 0.80 (near-biased).
- Per-cascade проекция солнца: sub-frustum → light-space → сфера для стабильности.
- Стекло не отбрасывает тень, жидкость отбрасывает.

**Q11. Что такое TAA и зачем?**
- Временное сглаживание: смешивает кадры, убирает дрожание камеры.
- 8-sample Halton-джиттер, YCoCg-зажим для цветовой истории.
- Поверх TAA — CAS (фильтр резкости).

**Q12. Что такое ray-marching и как реализован?**
- Трассировка лучей через воксели (DDA — Digital Differential Analyzer).
- Compute-шейдер скомпилирован, но graphics stream его пока не вызывает — это заглушка, Phase 7.

**Q13. Что такое контактная тень (CTSH)?**
- Короткая трассировка луча от фрагмента к солнцу, дополняет CSM.

**Q14. Что такое AOCC?**
- Локальное затенение полостей (фоновое затенение), 12 трассировок на фрагмент. Не полноценный SSAO.

**Q15. Зачем нужен локальный точечный свет, если есть солнце?**
- Сцена Voxel Laboratory имеет один на пресет обратно-квадратичный точечный свет в дополнение к направленному солнцу.
- Объёмный эффект, подсвечивает тёмные стороны.

**Q16. Как работает walk controller?**
- JPH::CharacterVirtual используется для обнаружения столкновений, наш воксельный решатель дополняет его для опоры игрока.

**Q17. Как работает авто-прыжок?**
- При включении J, каждый кадр проверяется: есть ли впереди блок высотой 1, можно ли перепрыгнуть.

**Q18. Что такое клеточный автомат (Fluid CA)?**
- Для жидкости: один тик — попытка падения вниз, иначе распространение в сторону.

### 3.3. Качество и метрики (6 вопросов)

**Q19. Какие тесты, сколько?**

- Baseline 14 из 14, 0.78 секунды debug, 0.06 секунды release.
- Runtime smoke 6 эталонных слоёв из 6.

**Q20. Почему покрытие тестами ниже 80%?**

- Визуальная корректность — через RuntimeSmoke.

**Q21. Какие метрики производительности?**
- VoxelLab reference shot: 110–130 FPS, время кадра 7–9 мс.
- Release: 19 МБ (vs 73 МБ debug), +1.5–2.5× FPS.

**Q22. Какие известные баги?**

- BUG-005 (cycle scene race): гонка дескрипторов, частично смягчена.

**Q23. Что отложено и почему?**

**Q24. Какие платформы поддерживаются?**
- Windows 10/11 (clang-cl 22) + Linux Arch (clang 22 native + libc++ 16).
- Обе сборки зелёные, 14/14 тестов.

### 3.4. Команда и организация (6 вопросов)

**Q25. Как распределена работа в команде?**
- 6 человек: тимлид и 5 участников по модулям.
- Тимлид: архитектура, выбор библиотек, DOD, ECS, Q&A.
- Тиммейты: конкретные модули (стек, воксельный мир, рендеринг, физика, демо).

**Q26. Какие решения принимали лично вы?**
- Выбор стека (C++26, Vulkan 1.4, Flecs, Jolt).
- DOD layout: `alignas(16)`, чанк 8×8×8.
- Hot/cold split: `std::expected` на холодных, `bool`+assert на горячих.
- Walk: воксельный решатель дополняет Jolt.
- Glass: не отбрасывает тень, жидкость отбрасывает.
- TAA: формат цвета B10G11R11 UFLOAT.
- 4-каскадный CSM с лямбдой 0.80.
- Release-пресеты: без `-ffast-math`, без `-march=native`.

**Q27. Какие были трудности в командной работе?**
- Согласование областей ответственности (scope) между модулями (VoxelWorld ↔ Renderer ↔ Physics).
- Multi-agent сессии: протокол в `AGENTS.md §7.2.6`.
- Инцидент 2026-06-10: `git checkout -- .` стёр uncommitted work. Урок: safety-net patch в `/tmp/`.

**Q28. Как тестировали итерации с BUG-004?**
- Tracked через `agent/voxelab-tremor-handoff-2.md`.
- Repro: статичная камера, VoxelLab, TAA ON, blend 0.10, jitter scale 1.0.
- Visual capture: `tools/linux/Invoke-ProjectVRuntimeSmoke.sh`.
- Попытка фикса: `90a45b4`, не устранила.

**Q29. Сколько коммитов и как организован workflow?**
- 100+ коммитов за 3,5 месяца.
- Conventional commits с type/scope (per `AGENTS.md §7.2.5`).
- Multi-agent координация через `agent/active-sessions.md`.
- Auto-close после коммита per `AGENTS.md §8.1`.

**Q30. Что бы вы улучшили в следующей итерации?**
- Phase 4 (Networking): сервер-авторитарный + клиентский предсказание.
- Phase 5 (SVO): гибридный SVO + чанки, SVO ray-marching для теней.
- Phase 6 (Fluid): полный клеточный автомат на GPU с диффузией и вязкостью.
- Phase 7 (Particles + Modding): система частиц, modding API.
- Phase 8 (SCP mechanics): неевклидова геометрия, порталы.
