# Vulkan 1.4 Phase 1 — Correctness Fixes

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:
> executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make ProjectV spec-compliant for Vulkan 1.4 by fixing the critical correctness gaps from
`docs/VulkanAudit-2026-07.md` §2 and §3.6/§3.2.

**Architecture:** Bump the API floor to 1.4, query `VkPhysicalDeviceVulkan14Features`, then fix dynamic-rendering
nesting/depth storage, HZB barrier/layout bugs, async-HZB dead code, cross-queue ownership, VCT clipmap barrier,
duplicate screenshot symbols, dead feature flags, and add a persistent `VkPipelineCache`. Each fix is isolated; the
phase ends with a clean validation-layer run.

**Tech Stack:** C++26, Vulkan 1.4 (SDK 1.4.350.1), volk, VMA 3.x, SDL3, Tracy.

## Global Constraints

- Vulkan 1.4 is the runtime minimum after this phase: `kDefaultMinVulkanApiVersion = VK_API_VERSION_1_4`.
- All changes must compile with `ninja -C build/linux-clang-debug ProjectV` and pass `ctest`.
- Debug builds run with `PROJECTV_ENABLE_VALIDATION=ON`; the runtime smoke must produce zero validation errors (except
  any pre-existing DDGI descriptor warnings documented in `agent/workspace.md`).
- No `git commit` by agents; propose commit messages in `AGENTS.md §5.1` format.
- One-line trailing comments only; `EVIL:` only for genuine undocumented hacks.

```cpp
inline VkSharingMode ChooseSharingMode(
    const VulkanContextState &context,
    const std::array<uint32_t, 2> &outQueueFamilies) noexcept
{
    if (context.hasDedicatedComputeQueue &&
        context.queueFamilyIndex != context.dedicatedComputeQueueFamilyIndex) {
        outQueueFamilies[0] = context.queueFamilyIndex;
        outQueueFamilies[1] = context.dedicatedComputeQueueFamilyIndex;
```

```cpp
    std::ifstream file(cachePath, std::ios::binary | std::ios::ate);
```
