# Vulkan 1.4 Phase 2 — Cleanup / Modernization

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:
> executing-plans to implement this plan task-by-task.

**Goal:** Close the contract divergences from `docs/VulkanAudit-2026-07.md` §3: descriptor-pool churn, sync1 remnants,
`EVIL` marker drift, file-length limits, dead BLAS compaction flag, and unused task-shader feature.

**Architecture:** Phase 1 already provides the 1.4 feature struct and pipeline cache. Phase 2 mechanically migrates the
remaining sync1 calls to sync2, resets descriptor pools instead of recreating them, adopts `LOAD_OP_NONE`/
`STORE_OP_NONE` and `maintenance5`/`maintenance6` where they simplify code, and performs hygiene (file splits + EVIL
audit).

**Tech Stack:** C++26, Vulkan 1.4 core, Tracy.

## Global Constraints

- All changes build with `ninja -C build/linux-clang-debug ProjectV` and pass `ctest`.
- Debug validation layers remain clean.
- File length must stay ≤ 600 lines after splits.
- One-line trailing comments; `EVIL:` only for genuine undocumented hacks.

### Task 2.1: Reset descriptor pools instead of recreating them

**Files:**

- Modify: `src/render/vulkan/VulkanGraphicsPipelineBindings.cpp:46-91`
- Modify: `src/render/vulkan/VulkanVoxelMeshingPipeline.cpp:160-198`
- Modify: `src/render/vulkan/VulkanMeshShaderPipeline.cpp:204-248`
- Modify: `src/render/vulkan/VulkanFluidCaPipeline.cpp:246-278`
- Test: existing descriptor-set tests + validation smoke

**Interfaces:**

- Consumes: existing `VkDescriptorPool` handles.
- Produces: `vkResetDescriptorPool` + `vkAllocateDescriptorSets` + `vkUpdateDescriptorSets` path.

- [ ] **Step 1: Replace destroy/create with reset in each refresh function**

Old pattern:

```cpp
if (render->graphicsDescriptorPool != VK_NULL_HANDLE) {
    vkDestroyDescriptorPool(context->device, render->graphicsDescriptorPool, nullptr);
}
// ... create new pool ...
```

New pattern:

```cpp
if (render->graphicsDescriptorPool != VK_NULL_HANDLE) {
    vkResetDescriptorPool(context->device, render->graphicsDescriptorPool, 0u);
}
if (render->graphicsDescriptorPool == VK_NULL_HANDLE) {
    // create pool only the first time
}
// allocate sets and update them
```

- Produces: `VkImageMemoryBarrier2` / `VkBufferMemoryBarrier2` inside `VkDependencyInfo`, submitted via

- [ ] **Step 1: Convert each sync1 barrier to sync2**

Mechanical mapping:

```cpp
VkImageMemoryBarrier2 b2{};
b2.sType = VK_STRUCTURE_TYPE_IMAGE_MEMORY_BARRIER_2;
b2.srcStageMask = old.srcStageMask; // now VkPipelineStageFlags2
b2.srcAccessMask = old.srcAccessMask;
b2.dstStageMask = old.dstStageMask;
b2.dstAccessMask = old.dstAccessMask;
b2.oldLayout = old.oldLayout;
b2.newLayout = old.newLayout;
b2.srcQueueFamilyIndex = old.srcQueueFamilyIndex;
b2.dstQueueFamilyIndex = old.dstQueueFamilyIndex;
b2.image = old.image;
b2.subresourceRange = old.subresourceRange;

VkDependencyInfo dep{};
dep.sType = VK_STRUCTURE_TYPE_DEPENDENCY_INFO;
dep.imageMemoryBarrierCount = 1u;
dep.pImageMemoryBarriers = &b2;
vkCmdPipelineBarrier2(cmd, &dep);
```

Do the same for buffer barriers.
