## 2. Что говорить verbatim (1:30, ~220 слов)

> «Рендеринг в ProjectV построен на Vulkan 1.4. Все эффекты встроены в основной forward-путь, без отдельных screen-space проходов. Расскажу про четыре ключевых эффекта.
>
> **Первый — каскадные тени, CSM.** У нас 4 каскада карты глубины 2048 на 2048. На каждый кадр процессор строит 4 матрицы проекции солнца — sub-frustum камеры переводится в light-space, фит по сфере для стабильности при повороте, экструзия кастеров вдоль направления солнца. Лямбда сплитов 0.80 — это near-biased, чтобы близкие объекты получали больше плотности теней. Стекло не отбрасывает тени, жидкость — отбрасывает, и это явно зафиксировано в наших решениях. Специальная полоса плавного перехода между каскадами убирает резкие границы.
>
> **Второй — контактные тени.** Это короткая voxel DDA-трассировка от фрагмента к солнцу, максимум 12 шагов. Дополняет CSM там, где texel size недостаточен, например под объектами на земле. Стекло пропускает, жидкость блокирует.
>
> **Третий — ambient occlusion, AOCC.** Локальный forward-path occlusion, 3 направления (1 normal + 2 перпендикулярных) по 4 шага = 12 DDA-трассировок на фрагмент. Это не полноценный SSAO, а компактный forward-shader occlusion term, встроенный в основной проход. Раньше был 5-tap, сократили до 3-tap для производительности.
>
> **Четвёртый — TAA, временное сглаживание.** Включено по умолчанию, потому что убирает дрожание камеры. Используем 8-sample Halton(2,3) jitter, YCoCg-зажим цветовой истории — это убирает ghosting на ярких участках. Семь триггеров инвалидации истории, включая изменение размера окна и перезагрузку мира. Поверх TAA работает CAS — high-pass фильтр резкости.
>
> **И пятый, бонусом — ray-marching.** Клавиша F12 переключает compute-шейдер, который трассирует DDA через packed voxel payload. Compute shader скомпилирован, но graphics command stream его ещё не вызывает — это запланированный Phase 7 follow-up, пока STUB. По умолчанию выключен. Передаю слово коллеге.»

## 3. Понятия (15 терминов, чтобы понимать что говоришь)

| Термин | Что это в одном предложении |
|---|---|
| **CSM (Cascaded Shadow Maps)** | Каскадные карты теней. Несколько карт глубины для разных диапазонов расстояний. |
| **Каскад** | Один диапазон расстояний (sub-frustum) с собственной shadow map. |
| **Lambda (λ) сплитов** | Баланс near-biased (λ=1) vs uniform (λ=0) распределения каскадов. У нас 0.80. |
| **PCF (Percentage-Closer Filtering)** | Взвешенное сглаживание теней через несколько сравнений глубины. |
| **Voxel DDA** | Digital Differential Analyzer — пошаговая трассировка луча через воксельную сетку. |
| **Amanatides-Woo** | Классический алгоритм DDA через регулярную сетку. |
| **Forward rendering** | Рендеринг без G-buffer, все эффекты в одном фрагментном шейдере. |
| **AOCC** | Ambient Occlusion Cavity Check — локальная окклюзия полостей. |
| **TAA (Temporal AA)** | Сглаживание через смешивание текущего кадра с историей прошлых. |
| **Halton sequence** | Квази-случайная последовательность для jitter'а, low-discrepancy. |
| **YCoCg** | Цветовое пространство: Y (luma), Co/Cg (chroma). Clamp по компонентам = меньше ghosting. |
| **CAS (Contrast Adaptive Sharpening)** | High-pass фильтр для повышения резкости после TAA. |
| **Neighbourhood clamp** | Clamp истории TAA по min/max соседей — убирает outliers. |
| **B10G11R11_UFLOAT** | Формат цвета: 11-бит лум, 11+10-бит chroma, 32-bit на пиксель. |
| **Ray-marching** | Per-pixel трассировка луча через объём для определения цвета. |

## 6. Если попросят «расскажите подробнее» (что вы можете раскрыть)

### Если спрашивают «зачем 4 каскада а не 1»:
> «Один shadow map 2048×2048 на всю сцену = texel size 64 метра. На близких объектах тени «зубчатые». С 4 каскадами near-biased — texel size 0.125 м на близких, 1-2 м на дальних. 512× плотность теней на близких объектах. Лямбда 0.80 даёт больше плотности вблизи.»

### Если спрашивают «что такое lambda 0.80»:
> «Это параметр practical split scheme: `split[i] = lerp(near*pow(far/near, i/n), near + (far-near)*i/n, lambda)`. Lambda=1 — чисто logarithmic, lambda=0 — чисто uniform. 0.80 — near-biased, проверено эмпирически на MeshingStress repro, baseline 0.65 был слишком generous to far receivers.»

### Если спрашивают «зачем XY sphere fit а не AABB»:
> «При вращении камеры AABB light-space меняется каждый кадр → texel size скачет, тени «дышат». Сфера rotation-stable: при повороте AABB sphere экстент не меняется (если сцена вписана). Стабильность важнее плотности на единицу площади.»

### Если спрашивают «что такое YCoCg clamp»:
> «В TAA мы храним предыдущий кадр в YCoCg цветовом пространстве. Luma (Y) отдельно, две chroma (Co, Cg) отдельно. При смешивании clamp'им каждую компоненту отдельно. В RGB clamp на ярких участках получается desaturation ghosting. YCoCg — меньше.»

### Если спрашивают «зачем нужен CAS после TAA»:
> «TAA с jitter'ом по своей природе слегка размывает картинку (мы семплируем между пикселями). CAS — high-pass фильтр: 4-угловое среднее соседей, вес от (1 - blend) * max(neighbors). Восстанавливает резкость, не возвращая aliasing.»

### Если спрашивают «почему B10G11R11 а не R16G16B16A16»:
> «B10G11R11 = 32-bit на пиксель, R16G16B16A16 = 64-bit. 2× экономия bandwidth, что критично на integrated GPU. 10-битный лум и 11-битная chroma — достаточно для PBR, потеря точности минимальна (визуально неразличима).»

### Если спрашивают «как работает ray-marching»:
> «Amanatides-Woo 3D DDA через packed voxel payload. На каждый пиксель: старт в позиции фрагмента, шагаем по 3D сетке чанков, на каждом шаге читаем packed material. Если solid — return shaded color. Push constants: world min, chunk size, chunk grid. Compute-шейдер скомпилирован, 64 max iterations. **ВАЖНО: на текущий момент — STUB**, graphics command stream его ещё не вызывает (только `fprintf` в stderr), полная интеграция — Phase 7 follow-up. По умолчанию OFF (F12 toggle, relocated с F6).»

### Если спрашивают «почему стекло не кастует тень»:
> «Это зафиксированное решение в `decisions.md §15`. Реальные tinted glass shadows требуют transmission/refraction path, что в 4-каскадном CSM не помещается. Пока стекло используется только для прозрачности (видно жидкость внутри шара). Жидкость кастует — это opaque shadow-map. Physical glass shadows — в R&D roadmap Phase 5+.»

### Если спрашивают «что такое AOCC и почему не SSAO»:
> «AOCC = Ambient Occlusion Cavity Check, локальный forward-path occlusion term, 12 DDA-трассировок на фрагмент. SSAO = screen-space ambient occlusion, требует depth/normal prepass. На нашем mainline нет prepass'а — всё в forward. SSAO отложен в Phase 5+, требует отдельной инфраструктуры. AOCC даёт 80% эффекта за 5% стоимости.»
