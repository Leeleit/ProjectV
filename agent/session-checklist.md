# Session Checklist

Обязательный пошаговый протокол для ведения сессии AI-агента в репозитории `ProjectV`.

---

## 1. Инициализация (Старт сессии)

- [ ] Выполнить `git status -uall` для фиксации исходного состояния дерева.
- [ ] Прочитать корневой `TODO.md` (определить текущие приоритеты и задачи).
- [ ] Прочитать файлы в директории `agent/` (`status.md`, `memory.md`, `decisions.md`, `active-sessions.md`).
- [ ] Зарегистрировать сессию в `agent/active-sessions.md` (добавить запись в блок «Активные сессии» с указанием
  `timestamp`, `scope`, `files-touched-intent` и `status: open`).

---

## 2. Во время работы (Инженерная гигиена)

- [ ] При решении сложных тем выполнять `web_search` (Exa) до написания кода (согласно `AGENTS.md §6.3`).
- [ ] Избегать коммитов файлов, не заявленных в `files-touched-intent` (соблюдать scope-дисциплину).
- [ ] Добавлять файлы только точечно: `git add <path>` (запрещено использовать `git add -A` и `git add .` без разбора).
- [ ] Перед деструктивными действиями на грязном дереве выполнить safety-net workflow (бэкап в `/tmp/`, показ диффа
  оператору, подтверждение согласно `AGENTS.md §6.4`).
- [ ] При спорных архитектурных решениях сверяться с принципами из `legacy/docs/philosophy/`.
- [ ] **Лимит отладки:** Если сборка или тесты падают 3–4 раза подряд с одной ошибкой, прекратить попытки отладки,
  зафиксировать `BLOCKED` в `agent/status.md` и позвать оператора.

---

## 3. После промежуточного коммита (Сессия остается OPEN)

*Сессия объединяет логическую работу и не закрывается автоматически после одного коммита.*

- [ ] (Опционально) Обновить поле `notes` в своей строке в `agent/active-sessions.md`.
- [ ] (Опционально) Отразить пройденный этап (milestone) в `agent/status.md` (в пределах одной строки).

---

## 4. Подготовка к завершению (Выполнение Definition of Done)

Выполняется после завершения основного объема работ перед финальным коммитом сессии.

- [ ] Убедиться, что проект успешно собирается (green build) на целевой платформе (если менялся код/сборка).
- [ ] Запустить тесты, затрагивающие измененные компоненты, убедиться в их успешном прохождении.
- [ ] Запустить приложение и проверить логи/консоль на отсутствие ошибок Vulkan Validation Layers.
- [ ] Проверить pre-commit gate для финального коммита (согласно `AGENTS.md §6.9`).
- [ ] Актуализировать `TODO.md` (отметить выполненные чекбоксы, скорректировать приоритеты, зафиксировать новые риски
  или идеи).
- [ ] Написать оператору краткое резюме проделанной работы и задать вопрос «**Что дальше?**».

---

## 5. Закрытие сессии (После явной команды оператора)

Выполняется только после того, как оператор подтвердил закрытие текущей задачи.

- [ ] Перенести запись сессии из блока «Активные сессии» в блок «Закрытые сессии» в `agent/active-sessions.md`.
- [ ] Проставить `status: closed`, время закрытия (timestamp) и хэш финального коммита.
- [ ] Обновить смежные файлы в `agent/` (добавить новые долговечные факты в `memory.md`, зафиксировать новые
  договоренности в `decisions.md` при их наличии).
- [ ] Удалить временные патчи из `/tmp/before_*`, созданные в рамках этой сессии (если деструктивные операции завершены
  успешно).

---

## 6. Исключительные ситуации

- [ ] **Сессия заблокирована (BLOCKED):** Если сборка сломана, pre-commit gate не пройден или возник конфликт версий —
  оставить сессию в статусе `open`, записать причину в `notes` в `agent/active-sessions.md` и прервать работу до
  фиксации проблемы оператором.
- [ ] **Принудительное прерывание (Abort):** Если работу продолжить невозможно, перевести сессию в статус
  `status: aborted`, указать причину в `notes` и оставить в блоке активных сессий для разбора.
